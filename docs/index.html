The Problem: Token Inefficiency at Scale

As Model Context Protocol (MCP) adoption scales, two critical patterns emerge that severely impact AI agent efficiency:

❌ Problem 1: Context Window Overload

  • Loading all tool definitions upfront consumes hundreds of thousands of tokens
  • Each tool definition occupies context space before any work begins
  • With thousands of tools, agents process massive token loads just to start
  • Tool descriptions alone can consume 150,000+ tokens

❌ Problem 2: Intermediate Result Bloat

  • Every intermediate result passes through the model's context
  • Data piped between tools gets processed twice unnecessarily
  • Large documents (transcripts, spreadsheets) may exceed limits
  • A 2-hour meeting transcript = 50,000+ extra tokens
Code Executor MCP github.com/ramhaidar/Code-Executor-MCP

The Solution: Code Execution with MCP

Instead of calling MCP tools directly, AI agents write TypeScript code that imports auto-generated wrapper files:

📂 Progressive Disclosure

Load only the tools needed for the current task. No upfront loading of thousands of definitions.

🔍 Context-Efficient Results

Filter and aggregate data in code before returning. Process 10,000 rows, return only 5.

🔄 Powerful Control Flow

Leverage loops, conditionals, and error handling with familiar programming patterns.

💾 State Persistence

Write intermediate results to files, build reusable skills. Resume work across sessions.

Code Executor MCP acts as a meta-MCP server — it provides tools to execute TypeScript code that can call other MCP servers:

Direct Tool Calls vs Code Execution

❌ Traditional Direct Approach

// Each call passes through model context

TOOL CALL: gdrive.getDocument(
  documentId: "abc123"
)
→ Returns full transcript (50K tokens)
→ Loaded into model context

TOOL CALL: salesforce.updateRecord(
  objectType: "Lead",
  data: { Notes: "[entire transcript]" }
)
→ Model rewrites entire transcript again

Total: ~100,000 tokens

✅ Code Execution Approach

import * as gdrive from './servers/gdrive';
import * as sf from './servers/salesforce';

// Data stays in execution environment
const doc = await gdrive.getDocument({
  documentId: "abc123"
});

await sf.updateRecord({
  objectType: "Lead",
  data: { Notes: doc.content }
});

console.log("Done!");

Total: ~200 tokens (99.8% savings)

Import Patterns & Common Mistakes

✅ Correct Patterns

// Pattern 1: Import entire server
import * as ctx7 from
  '../servers/context7/index.js';
await ctx7.resolveLibraryId.call({
  libraryName: "react"
});

// Pattern 2: Import specific tool
import { resolveLibraryId } from
  '../servers/context7/index.js';
await resolveLibraryId.call({...});

// Pattern 3: Direct file import
import * as tool from
  '../servers/context7/resolve-library-id.js';
await tool.call({...});

❌ Common Mistakes

// Missing /index.js
import { x } from '../servers/context7'
// ❌ ESM requires explicit paths

// Missing .js extension
import { x } from '../servers/ctx/index'
// ❌ Must include .js for ESM

// Calling tool directly
await resolveLibraryId({...})
// ❌ Must use .call() method

// Non-existent export
import { context7Tools } from ...
// ❌ Use actual tool names

Security Considerations

Important security notes when deploying Code Executor MCP:

⚠️ Unsandboxed Execution

The execute_code tool runs arbitrary TypeScript without sandboxing. Only use in trusted environments.

🔐 Credential Exposure

Server configs in mcp.json may contain sensitive credentials. Protect with appropriate permissions.

📁 Workspace Isolation

Executed code operates from workspace/. File operations are relative. Don't store sensitive data there.

Privacy Benefits

When agents use code execution, intermediate results stay in the execution environment by default. Data you don't log never enters the model's context — enabling privacy-preserving workflows where sensitive information flows between tools without model exposure.
